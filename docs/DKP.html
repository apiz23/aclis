01Ringkasan Projek

ACLIS menukar pengurusan manual data kepimpinan kampung — yang sebelum ini tersebar dalam pelbagai spreadsheet — kepada satu platform web terpusat.

Objektif (memetakan kertas cadangan)

  1. Mereka bentuk seni bina sistem berorientasi objek daripada keperluan fungsi / bukan fungsi.
  2. Membina platform web yang memusatkan data kampung, memperkemas pelaporan, dengan papan pemuka pemantauan berbantukan AI.
  3. Menilai fungsi, kebolehgunaan dan keberkesanan (pengujian kebolehgunaan + SUS).

Bagaimana Ia Berfungsi (senario utama)

  • Admin Daerah merekod kampung, penduduk & B40, pemimpin, dan penilaian prestasi; menyemak laporan dan isu seluruh daerah.
  • Ketua Kampung menghantar laporan bulanan dan melog isu untuk kampungnya sendiri sahaja.
  • Penghulu menyemak (read-only) data kampung dalam mukimnya.
  • AI meringkaskan laporan panjang, mengategorikan isu, dan menyerlahkan trend — semua data dilindungi (PII direntas sebelum keluar ke cloud).

Justifikasi Stack (untuk laporan/tesis)

  • Next.js + FastAPI berasingan — pemisahan 3-tier yang bersih → seni bina sistem berorientasi objek yang jelas untuk rajah use-case/ERD.
  • Python backend — membuka ruang untuk model tempatan (Ollama) tanpa pertukaran bahasa.
  • Supabase — menyelesaikan auth silang-lapisan (satu JWT disahkan oleh kedua-dua Next.js dan FastAPI) + storan foto + Postgres dalam satu kotak percuma.
  • Kebolehtukaran AI — semua panggilan AI melalui AIProvider: GroqProvider (kini), OllamaProvider (tempatan), ClaudeProvider (masa depan).

08Kawalan Akses (RBAC)

Tiga peranan dengan skop data berbeza. Dikuatkuasakan dua lapisan: FastAPI (dari tuntutan JWT) dan RLS di peringkat DB. UI Next.js hanya menyembunyikan butang yang tidak boleh digunakan (pertahanan kedua, bukan sempadan keselamatan).

FungsiAdmin DaerahKetua KampungPenghulu
Lihat kampungSemuaKampung sendiriMukim sendiri
Tambah / edit kampungYa——
Rekod penduduk & B40Ya——
Hantar laporan bulananYaKampung sendiri—
Log isu komunitiYaKampung sendiri—
Semak papan pemukaPenuhTerhadTerhad
Penilaian pemimpinYa——
Log auditYa——

Pelaksanaan

  • Backend: peranan dibaca daripada app_metadata.role dalam JWT; peranan tidak dikenali → 403 (tiada lalai).
  • Skop tenant: get_user_scope() menyelesaikan ID kampung/leader yang dibenarkan per permintaan, dengan cache TTL 60 saat (mengurangkan 3–5 pertanyaan DB kepada 0 pada hit cache).
  • DB: RLS aktif pada semua jadual; auth_role() kembali kosong jika peranan tiada.

09Lapisan AI

Tiga ciri AI — terhad skop mengikut kertas cadangan (tiada ML penuh, tiada ramalan).

CiriFungsi
Ringkasan laporanMemekatkan laporan bulanan kepada ringkasan 2–3 ayat untuk semakan pantas.
Kategorisasi isu automatikMenandai isu masuk (infrastruktur / jalan / sosial) kepada issue.ai_category.
Insight trendMenyerlahkan isu berulang / corak lewat serahan untuk papan pemuka daerah.

Antara muka

class AIProvider(Protocol):
    def summarize_reports(self, reports: list[ReportText]) -> Summary: ...
    def categorize_issue(self, issue_text: str) -> Category: ...
    def detect_trends(self, records: list[Record]) -> list[Insight]: ...

Pembekal

  • GroqProvider — semasa, model llama-3.3-70b-versatile (dipilih melalui AI_PROVIDER=groq).
  • MockProvider — lalai (AI_PROVIDER=mock), untuk demo luar talian tanpa API key.
  • OllamaProvider / ClaudeProvider — pilihan masa depan (tempatan / kualiti tinggi).
Redaksi PII (syarat bukan fungsi) Sebelum sebarang teks meninggalkan mesin ke pembekal AI cloud, PII direntas (nombor IC, alamat penuh, nama jika tidak perlu). Ciri AI beroperasi pada kandungan laporan/isu dan trend, bukan medan identiti — jadi redaksi tidak menjejaskan kualiti dan memberi cerita privasi yang kukuh untuk pembentangan.

Tipografi

  • Headings (font-heading): Barlow Semi Condensed, berat 600 — autoriti institusi terkondensat.
  • Badan / UI (font-sans): Figtree 400/500/600/700 — boleh dibaca pada 13–16px dalam jadual padat.
  • Mono (font-mono): JetBrains Mono — ID, kod, data mentah sahaja.
  • Nombor stat & jadual: sentiasa tabular-nums.

Bentuk & Komponen

  • --radius: 0.375rem — lebih ketat daripada lalai shadcn (0.5rem).
  • Bingkai atas bayang-bayang sebagai pemisah utama — sistem berbordered, bukan kad terapung.
  • Sidebar sentiasa navy gelap, emas menanda item aktif — satu-satunya permukaan warna komited.
  • Carta: emas siri utama, navy-teal kedua; garisan grid malap, tiada isian 3D/gradien.

Prinsip reka bentuk

  1. Data dahulu — jadual dan nombor adalah permukaan UI utama.
  2. Kekangan bermaruah — tiada perhiasan; setiap elemen berhak pada tempatnya.
  3. Hierarki jelas — kontras tipografi kuat antara saiz tajuk.
  4. Kebolehbacaan institusi — dioptimumkan untuk membaca baris jadual di bawah pencahayaan pendarfluor pejabat.
  5. Tiada persahabatan palsu — elak glassmorphism, teks gradien, jalur aksen kiri.

Aksesibiliti: WCAG 2.1 AA (perkhidmatan sektor awam); teks & placeholder ≥ 4.5:1 kontras; mod cahaya sahaja; hormat prefers-reduced-motion.

Sebelum teks ke pembekal AI cloud, IC/alamat/nama yang tidak perlu direntas. Dengan Ollama tempatan, data tidak pernah meninggalkan mesin — redaksi menjadi tali pinggang dan suspender.

12Import Data

Jangan pandang rendah — tugas bukan-AI paling sukar Fail sumber utama ID KKG UBAH BETUL .xlsx ialah 37MB, kotor: pelbagai dataset bercampur (kepala kampung Pontian + penilaian Johor Bahru + registri masjid Kulaijaya yang bocor masuk), satu sheet per mukim, dan 95 foto terbenam dalam sel.
  1. Tulis skrip import one-off (pandas + openpyxl).
  2. Kenal pasti dan buang baris masjid Kulaijaya yang di luar skop.
  3. Normalisasikan sheet per-mukim ke dalam skema relasional.
  4. Ekstrak 95 imej terbenam → muat naik ke Supabase Storage → paut ke Leader.photo_url.
  5. Sahkan konsistensi IC/format; log tolakan untuk semakan manual.
